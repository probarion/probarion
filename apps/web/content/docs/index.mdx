## What happens to one invoice

The model may advise. Code decides. The contract has the last word.

<Flow>

1. **Owner** Signs a mandate: who gets paid, how much per payment and in total, how many times, until when, which agent key may use it, and above what amount a person must approve.
2. **Code** Decides to allow the payment, hold it or refuse it, with built-in rules that cannot be removed. A model may advise, but it cannot widen the mandate. The SDK signs the decision into the ledger before anything is sent, refusals included. If code refuses, nothing is sent.
3. **Agent** Asks to spend. Its `spend` request carries a mandate id, an amount, a ref and two hashes, one of them the signed decision's. It has no field for a payee.
4. **Contract** Runs 14 checks in a fixed order. It pays the mandate's payee, holds the spend for an approver, or refuses with a code such as `NoMandate`. The SDK signs that outcome into the ledger.
5. **Anyone** Checks a published record. Each ledger entry is chained by hash to the one before, and the SDK anchors the root on the vault with the ledger key. The verifier runs checks a to i with no account and ends with PASS, FAIL or UNPROVEN.

</Flow>

Follow the whole path in [How one payment works](/docs/start/how-one-payment-works), or see each check in [How a payment is checked](/docs/concepts/payment-checks).

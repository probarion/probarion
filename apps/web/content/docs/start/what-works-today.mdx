### Test USDC on testnet

The testnet faucet is Preview: it is built and tested, and its key is set on probarion.xyz. On 2026-11-09 its button minted 25 test USDC into the testnet demo vault, `demo.vaults.probarion.testnet`.

## What does not exist

None of these is on the status list as Planned. The README's known limitations, such as no Content-Security-Policy yet, and the threat model's [known gaps](https://github.com/probarion/probarion/blob/main/docs/THREAT_MODEL.md#known-gaps) list the rest.

### Outbound webhooks

The code has no webhook that calls a server of yours. Its one webhook is incoming: Telegram calls `/api/telegram/webhook` for the alert bot. To follow a vault yourself, index the NEP-297 events its contract logs (`EVENT_JSON:` lines with the standard `probarion`).

### A public HTTP API for agents

The console's invoice API answers only a signed-in owner or approver, on a same-origin request. An agent pays through the SDK, in its own process: [let an agent pay](/docs/build/let-an-agent-pay) shows how. The other agent interface is the [MCP server](#mcp-server), which runs beside the agent over stdio and pays through the same SDK.

### Pricing

There is no price list and no paid plan. The [terms](/terms) say "Probarion charges nothing for the console." Your wallet pays for the transactions you sign and for the storage deposits: when you create the vault, and for each mandate. The agent's spends and the ledger key's anchors burn gas from the vault's own NEAR, up to each key's allowance, so the vault needs some NEAR of its own. [Vaults, roles and keys](/docs/concepts/vaults-roles-and-keys) explains the allowances.

### A third-party audit

No third party has audited this code, as the note under the status list says. [SECURITY.md](https://github.com/probarion/probarion/blob/main/SECURITY.md#reporting-a-vulnerability) says how to report a vulnerability.

## How this list stays true

The status list is `STATUS.rows` in [`apps/web/src/lib/site/facts.ts`](https://github.com/probarion/probarion/blob/main/apps/web/src/lib/site/facts.ts), the module the landing page renders. The docs home and this page render the same rows and turn each row's tone into a docs word: `live` becomes Live, `work` becomes Preview and `plan` becomes Planned.

Tests hold the list to the repository:

- [`apps/web/test/site-facts.test.ts`](https://github.com/probarion/probarion/blob/main/apps/web/test/site-facts.test.ts) holds each row to the words of its README Status row, and pins the exact rows, ids and pills. A row cannot change unless that test changes with it.
- [`apps/web/test/docs-reference.test.ts`](https://github.com/probarion/probarion/blob/main/apps/web/test/docs-reference.test.ts) checks that every row maps to Live, Preview or Planned and has a stable id, the anchor of its row on this page.
- [`apps/web/test/docs-pages.test.ts`](https://github.com/probarion/probarion/blob/main/apps/web/test/docs-pages.test.ts) checks that this page renders the table.

The sections under [also in the source](#also-in-the-source) and [what does not exist](#what-does-not-exist) are written by hand, so no test holds them to the README. Where the two differ, the README Status table and the code it links are the record.

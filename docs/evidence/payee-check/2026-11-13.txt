Payee check, read-only, on NEAR testnet and mainnet (2026-11-13, UTC)

What this records
-----------------
`probarion payee check` answers allow, warn or block about a payee before a mandate names it, with one reason per
check: the account exists, Probarion's seed blocklist, a lookalike of the vault's payees, contract code, new or code
changed in about 7 days (on Base, nonce 0, a weaker sign that shows no age), and whether the vault paid it before.
It is in this repository (packages/core/src/payee-check.ts, packages/sdk/src/payee-signals.ts,
packages/cli/src/commands/payee.ts), not in npm 0.1.1. These runs used the repository's CLI, built from the branch
chore/integrate-2026-11-14 in a clone.

Each run reads the chain with read-only requests: NEAR RPC views and block headers (FastNEAR, and its archival node
for the block about 7 days back) and, for the Base payee, Base JSON-RPC (https://mainnet.base.org). It signs
nothing and sends no transaction. The verdict is advice for the owner; it changes nothing on chain.

Exit codes: 0 allow, 2 warn, 1 block (or a check that could not run), 64 usage error.

payees get WARN, not ALLOW: probarion-duong.near was new within about 7 days on this date, and the Base payee has
sent no transaction (nonce 0). A lookalike check compares the payee with this vault's payees only. The code is
unaudited. The mainnet payments so far are tests to the owner's own addresses.
